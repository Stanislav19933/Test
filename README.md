# InstrumentCard AI

**Локальный MVP для генерации черновиков B2B-карточек контрольно-измерительных приборов.** Веб-интерфейс принимает JSON товара, использует Z.ai API (`glm-4.7-flash`, резерв `glm-4.5-flash`), возвращает SEO-заголовок, SEO-описание, ключевые характеристики, 3–5 поисковых запросов и коммерческий блок. Контент-менеджер может скачать JSON или Markdown и проверить предупреждения о недостатке данных.

> ⚠️ Итог — черновик для проверки человеком. Автоматический анализ чисел уменьшает риск ошибок, но **не гарантирует фактическую корректность** каждого предложения модели.

## Быстрый запуск

Требуется **Python 3.12+** и бесплатный ключ Z.ai: https://z.ai/manage-apikey/apikey-list.

```bash
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows (PowerShell):
# .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Задайте ключ **только локально**, не записывайте его в код:

```bash
# Linux / macOS
export ZAI_API_KEY="ваш_ключ"

# Windows PowerShell
# $env:ZAI_API_KEY="ваш_ключ"
```

Или скопируйте `.streamlit/secrets.toml.example` в `.streamlit/secrets.toml` и впишите ключ: файл с секретами исключён из Git через `.gitignore`.

Запустите:

```bash
streamlit run app.py
```

Откройте адрес, показанный в терминале (обычно `http://localhost:8501`).

Без API-ключа доступен просмотр **двух редакторских примеров**: выберите товар и нажмите «Показать редакторский пример (без API)». Это заранее подготовленный **человеком** текст, а не выдаваемый за реальный вызов модели результат. Для проверки реальной LLM-генерации нужен ключ.

## Работа с приложением

1. Загрузите один из двух примеров или свой `.json` (не больше 128 КБ), либо вставьте JSON в текстовое поле.
2. Ознакомьтесь с предупреждениями об отсутствующих полях/характеристиках.
3. Нажмите **«Сгенерировать карточку»**.
4. Проверьте заголовок, описание, характеристики, запросы, коммерческий блок и раздел контроля качества.
5. Скачайте результат в JSON или Markdown.

Входной формат:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5"
  },
  "description": "Прибор предназначен для измерения избыточного давления.",
  "expected_specs": ["диапазон измерений", "класс точности", "диаметр корпуса"],
  "source_url": "https://example.org/item"
}
```

Поддерживаются исходные поля из задания: `name`, `manufacturer`, `specs`, `description`. Дополнительные **необязательные** поля: `expected_specs` — названия характеристик, которые нужно отобразить, даже если значений нет; `source_url` — адрес источника. Неизвестные значения отображаются **«данных нет»**, никакие параметры не подставляются автоматически.

## Примеры

| Товар | Исходный JSON | Иллюстративный результат |
|---|---|---|
| CEM DT-83 — мини-термометр с измерением влажности | `samples/dt83.json` | `samples/dt83_example_result.json`, `.md` |
| РОСМА ТМ-510 — показывающий манометр | `samples/tm510.json` | `samples/tm510_example_result.json`, `.md` |

Источники — публичные карточки магазина:
- https://www.souz-pribor.ru/product/dt-83/
- https://www.souz-pribor.ru/product/tm-510/

**Важная оговорка:** исходный адрес фида `https://www.souz-pribor.ru/yml/any/feed.xml` не удалось скачать для проверки: попытки получить большой XML завершались ошибкой размера содержимого / тайм-аутом. Поэтому наличие именно этих двух позиций **в YML-фиде не подтверждено**. Образцы подготовлены по доступным карточкам самого магазина. После получения файла фида следует сверить записи `<offer>` и при необходимости заменить образцы.

Примеры результатов составлены вручную для демонстрации ожидаемого качества формата (`*_editorial_example.json` содержит текстовые поля, `*_example_result.json` и `.md` — полную карточку); реальные ответы API могут отличаться.

## Архитектура и безопасность

```text
JSON / файл / пример
       │
       ▼
Pydantic: типы и пустые поля
       │
       ├──────────────► deterministic specs + «данных нет»
       │
       ▼
Z.ai API: GLM-4.7-Flash
(JSON object + проверка Pydantic: SEO + запросы + коммерческий блок)
       │
       ▼
Проверки длины, числа запросов, новых числовых токенов
       │
       ├── проблемы? одна повторная генерация → явные предупреждения
       ▼
Карточка + отчёт о проверке + экспорт JSON/Markdown
```

- `instrumentcard/models.py` — схемы входа и результата.
- `instrumentcard/zai_client.py` — промпт, API, разбор кодов ошибок Z.ai, короткие повторы, две бесплатные модели.
- `instrumentcard/quality.py` — проверка структуры и числовых значений, маркировка пропусков.
- `instrumentcard/service.py` — сценарий генерации и повторной попытки.
- `instrumentcard/formatting.py` — экспорт Markdown.
- `app.py` — Streamlit-интерфейс.
- `tests/` — тесты без сетевых запросов, включая подставные ответы LLM.

### Промпт и защита от недостоверных данных

Промпт запрещает модели придумывать характеристики, переводить единицы и объединять параметры разных исполнений прибора. Описательные поля генерируются через режим JSON object и локальную проверку схемы Pydantic; список технических характеристик берётся только из пользовательского JSON. Вводные данные передаются как данные, а не инструкции. Код проверяет:

- заголовок (1–70 символов);
- SEO-описание (строго 800–1200 символов; нарушения явно помечаются);
- 3–5 непустых поисковых запросов;
- новые **числовые значения** в сгенерированном тексте (проверка на присутствие чисел во входе);
- наличие основных полей и ожидаемых характеристик, если они заданы.

При ошибках формата предусмотрена **одна дополнительная попытка**, требующая 900–1050 символов для слишком короткого описания. Если формат остаётся неправильным, произвольный JSON даёт **неполный черновик**, который не кэшируется как готовый. Для двух неизменённых встроенных товаров вместо неудачного результата показывается отдельно подписанный ручной пример. При выборе между версиями приоритет — отсутствие неподтверждённых числовых сведений. Смысловая корректность и принадлежность параметров конкретной модификации проверяются редактором.

### Обработка ошибок

Обрабатываются неправильный JSON, не-объектный JSON, неожиданные типы, пустое название/описание, отсутствие API-ключа, недоступность сервиса, 401, 429, HTTP-ошибки, несовпадение структуры ответа. Настоящий ключ не записывается в исходники и не передаётся в скачиваемые результаты.


### Защита от временных ошибок Z.ai

Сервис различает внутренние коды HTTP 429: `1302` (лимит запросов), `1305` (перегрузка), `1113` (нет средств/прав тарифа), `1308` и `1310` (исчерпание квоты). Для временного отказа делает до двух попыток на `glm-4.7-flash` с задержкой, после чего пробует **только бесплатную** `glm-4.5-flash` (также до двух попыток). Одновременные запросы в одном Python-процессе упорядочены. Результаты, прошедшие проверки формата и числовых значений, сохраняются в кэше Streamlit на один час. Вторичная ошибка API при исправлении текста не уничтожает уже полученный черновик; он выводится с предупреждениями.

**Гарантия доступности не предусмотрена бесплатными условиями Z.ai.** При недоступности обеих моделей для пользовательского JSON показываем понятное сообщение. Если API не ответил либо выдал некорректный формат, приложение **не подменяет ответ ручным текстом**. Для всех товаров отображается диагностическая ошибка либо реально полученный неполный черновик. Это не выдаётся за ответ AI. Также есть отдельная кнопка «Показать редакторский пример (без API)». Лимиты аккаунта: https://z.ai/manage-apikey/rate-limits. Коды ошибок: https://docs.z.ai/api-reference/api-code. Платные модели не вызываются.

**Кэширование:** только ответы, прошедшие контроль длины, поисковых запросов и числовых значений, сохраняются в кэш на один час; нарушающие требования ответы не кэшируются.

## Тесты

```bash
python -m unittest discover -s tests -v
python -m compileall -q app.py instrumentcard tests
```

GitHub Actions выполняет их автоматически без API-ключа. Отдельно предусмотрен ручной end-to-end тест с реальным API: сгенерировать обе карточки и сверить их с источником.

## Развёртывание на Streamlit Community Cloud

1. Создайте публичный GitHub-репозиторий и загрузите в его корень содержимое этого проекта.
2. На https://share.streamlit.io создайте приложение с `app.py` в качестве entry point.
3. В **Settings → Secrets** добавьте `ZAI_API_KEY = "..."`. Не коммитьте `secrets.toml` в Git.
4. Проверьте генерацию на двух товарах и сохраните публичную ссылку.

Тарифы и доступность моделей у внешнего провайдера могут измениться: https://docs.z.ai/.

## Ограничения / возможные улучшения

- Проверка чисел обнаруживает часть галлюцинаций, но **не** все ложные факты, изменение единиц при совпадающих числах или подмену характеристик одного исполнения другим. Можно дополнить проверкой фактов на уровне цитат/источников и экспертным review.
- Извлечение параметров из произвольного PDF, OCR, парсинг полного YML-фида, учёт нескольких модификаций одной карточки и массовая обработка специально не реализованы: они выходят за рамки задания.
- Бесплатный API может возвращать 429 и при минимальной нагрузке; ограничитель вызовов действует только в пределах одного процесса, а кэш и резервная модель снижают вероятность ошибки, но не исключают её.
- При недостатке исходных фактов короткое SEO-описание явно помечается незавершённым, а не выдаётся за соответствующее диапазону 800–1200 символов.
- Нет базы данных, CMS, аккаунтов и продакшн-деплоя: для тестового они не требуются.

## Соответствие тестовому заданию

Все 5 выходных блоков формируются, технические параметры сохраняются из исходных данных, ошибки и пропуски обрабатываются, доступен копируемый/скачиваемый результат, README содержит шаги запуска, примеры, архитектуру и ограничения. Реальный внешний API-вызов и размещённая веб-демонстрация требуют действующего ключа и отдельной проверки.

### Прозрачность результатов (SEO v4)

Ручные примеры никогда не появляются при нажатии «Сгенерировать карточку». Если модель вернула невалидный JSON, отсутствующие поля или короткий текст, сервис показывает точную категорию ошибки либо полученный незавершённый черновик. Поддерживаются JSON-ответы с лишними служебными полями и целые JSON-объекты даже при `finish_reason=length`; четыре обязательных поля проверяются Pydantic. В журнал пишутся только имя модели и категория ошибки — без ключа и исходных данных.


### Улучшенная генерация SEO (SEO v5)

Основной запрос к Z.ai остаётся **одним**. Промпт предписывает сформировать
три смысловых абзаца — назначение (280–350 символов), факты о характеристиках
(320–400), задачи и ограничения выбора (280–350). Все сведения берутся только
из входного JSON, повторения и новые технические параметры запрещены.
Результирующее поле `seo_description` должно иметь 800–1200 символов.
Количество символов проверяется Python-кодом, а не доверием к самооценке LLM.

Если текст не прошёл проверку, допустима **одна корректирующая генерация**:
вместе с замечаниями модель получает собственный предыдущий ответ и план
расширения. Это исправляет прежнюю проблему, когда система просила
«исправить предыдущий ответ», но не передавала сам черновик.
При нехватке исходных фактов короткий черновик остаётся явно неполным;
код не дописывает выдуманные характеристики и не маскирует ошибку.
